# Счётная машина FastCalc / The FastCalc (pwn/hard)

## Запуск

```bash
CTF_FLAG='InnoCTF{...}' docker compose up -d --build
# http://127.0.0.1:13444
```

Состав: сервис `challenge` (Flask-веб) плюс сервис `vm` (C-ВМ) — они
общаются через unix-сокет в общем томе.

## Условие (для игроков)

**RU:** Древняя счётная машина FastCalc всё ещё в строю: на её API завязаны
соседние сервисы, и трогать её никто не решается. Недавно машине разрешили
удалённо обновлять прошивку. Узнайте, что ещё она согласится показать.

**EN:** The ancient FastCalc calculating machine is still in service: neighbouring
systems depend on its API, and nobody dares touch it. Recently the machine was
allowed to accept remote firmware updates. Find out what else it can be made
to show.

## Решение

1. На входе — гость и админ. Проверка JWT написана вручную: для HS256
   подпись сверяется, а `alg:none` принимается без проверки. Форжим
   admin-токен, меняв `role` на `admin` и выкинув подпись.
2. Админу доступны `GET /api/firmware`, `POST /api/upload`, `POST /api/reset`.
   Прошивка — образ FWM2: 36-байтовый заголовок (magic, версии, длины, entry,
   flags, crc32, key) плюс XOR-замаскированный payload с CRC.
3. Уязбимость — в VM: `PICK`/`PUT` работают со слотами 0..11, хотя
   регистров 8. Слот 10 — `halt_slot` (адрес завершающего колбэка),
   слот 11 — `secret_slot` (адрес `reveal_flag`), оба замаскированы
   cookie процесса. `HALT` вызывает `halt_slot ^ cookie`.
4. Записать слот 10 можно только после чтения слота 11 (`probe_armed`),
   поэтому утечка и перезапись — два отдельных запроса.
5. Прошивка A: `PICK r3,11; OUTHEX r3; HALT r3` — утекает адрес
   `reveal_flag ^ cookie`. Прошивка B: `MOVI r3,<утёкший адрес>; PUT 10,r3;
   HALT r3` — колбэком становится `reveal_flag`, и калькулятор печатает флаг.

Подробное описание — в [WALKTHROUGH.md](WALKTHROUGH.md).

## Непредусмотренные решения (более короткий путь) и потенциальные проблемы

1. **Короткий путь без утечки.** Оба слота хранят указатели, замаскированные
   одним и тем же cookie, поэтому XOR-разница маску сокращает:
   `halt_slot ^ secret_slot = &finish_result ^ &reveal_flag` — константа
   линковки, не требующая ни утечки, ни знания PIE/cookie. Два запроса:
   - запрос 1 — армим `probe_armed` (запрос обязан завершиться без ошибки:
     «fell off image» ставит `error` и не армит): `PICK r3,11; HALT r3`;
   - запрос 2 — `PICK r3,10; PICK r4,11; XOR r5,r3,r4; XOR r3,r3,r5;
     PUT 10,r3; HALT r3` — `HALT` вызывает `reveal_flag`, флаг печатается
     в ответе `/api/calculate`.
   Это та же уязвимость (слоты 10/11), категорию не меняет; штатный путь
   через `OUTHEX`-утечку остаётся основным решением. Закрыть, если
   захочется, можно, храня в слотах указатели с разными необратимыми
   масками (например, умножение на разные нечётные константы).
2. Прошивка — общее состояние инстанса: работает последняя загруженная
   (игроки могут перезаписывать firmware друг друга — это дизайн задания).
3. VM обрабатывает запросы последовательно: зависший клиент держит VM до
   2 с (таймаут веб-сервиса), при очереди `/api/calculate` отвечает 503.
   На одиночном инстансе несущественно.
4. Утечки флага без pwn нет: флаг живёт в контейнере `vm`
   (`/run/case/flag`, `0400 fastcalc`), веб-контейнер к нему не имеет
   доступа; из веба флаг достаётся только через колбэк ВМ. Остальные
   веб-входы закрыты (`alg:none` — интенд; поля/размеры/типы валидируются,
   отладчик Flask не включён).
