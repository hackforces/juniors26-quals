# Испытательный стенд / The Test Bench (pwn/easy)

- Порты: `13442` (nc, интерактив; `PORT`) и `13443` (http, хэндаут; `PORT_HTTP`)
- Флаг: только из env `CTF_FLAG` (кладётся в `/run/case/flag` на старте
  контейнера, читается сервисом при старте)
- Хэндаут: `http://<host>:13443/easy-shelvecode-files.zip` — тот же ELF, что в сервисе
  (без него раскладка арены — гадание)

## Запуск

```bash
CTF_FLAG='InnoCTF{...}' docker compose up -d --build
nc 127.0.0.1 13442
```

## Условие (для игроков)

**RU:** В закрытой мастерской стоит испытательный стенд: подаёшь короткую
перфокарту с заданием — он прогоняет её и докладывает только исход, без
подробностей. На самом стенде выбита маркировка изделия. Прочитайте её.

**EN:** In a sealed workshop stands an old test bench: feed it a short punch card
with a task, and it runs the job, reporting only the outcome — no details. The
product's nameplate is etched right into the bench. Read it.

## Решение

1. Сервис принимает до 64 байт shellcode, каждый байт обязан быть чётным
   (`value & 1 == 0`), после чего выполняет его в форке и сообщает только
   исход: `EXIT` / `SIGSEGV` / `SIGFPE` / `SIGILL` / `SIGALRM`.
2. Флаг лежит в `arena.flag` сразу за буфером `arena.code` (смещение
   `0x1005`), страница арены сделана RWE, PIE-база неизвестна.
3. `e8 00 00 00 00; 5e` (call 0; pop rsi) даёт адрес внутри shellcode —
   независимо от PIE. `8a 86 disp32` читает байт флага по `rsi+disp32`.
4. Чётные байты запрещают syscall и ret, но оставляют `hlt` (SIGSEGV),
   `div al` с нулём (SIGFPE), `62 00 00 00` (SIGILL) и зацикленный `loop`
   (SIGALRM от родительского таймаута 150 мс) — готовый 2-битный оракул.
5. На каждый байт флага — 4 запроса по 2 бита; 64 × 4 соединения
   восстанавливают флаг целиком.

Подробное описание — в [WALKTHROUGH.md](WALKTHROUGH.md).

## Непредусмотренные решения и потенциальные проблемы

Аудит unintended-векторов (по `src/sandbox.c`):

1. **Self-modifying code.** Страница арены RWE, а запрет нечётных байт
   действует только на входной payload: арифметикой по чётным байтам
   (`and`/`shl`/`add` по памяти; нечётное значение можно прочитать прямо
   из флага) теоретически можно собрать нечётный опкод — вплоть до
   `0f 05` (syscall) и уйти от оракула. На практике вектор закрыт
   бюджетом: 64 байта не вмещают даже посимвольную сборку строки
   `"/bin/sh"` (~120+ байт кода), а канала вывода у shellcode нет —
   child закрывает `client`, fd 0/1/2 уходят в логи контейнера, флаг
   есть только в арене. Максимум, что даёт SMC, — испортить арену или
   убить родителя (DoS). Радикальное закрытие, если понадобится: в
   child-ветке перед прыжком `mprotect(страница, len, PROT_READ|PROT_EXEC)`
   — запись в код станет SIGSEGV, оракул (чтение флага) не сломается.
2. **Утечки без pwn нет.** Хэндаут — тот же ELF без флага; busybox httpd
   раздаёт только zip с бинарником; флаг материализуется в `/run/case/flag`
   (`0400 ctf:ctf`) на старте контейнера.
3. **DoS медленным клиентом.** `handle_client` обрабатывает соединения
   последовательно: клиент, зависший на промпте `length> `, блокирует
   остальных (инстанс один). Если понадобится — `SO_RCVTIMEO`/`alarm()`
   на клиента.
