# mini-vm — разбор решения

Цель: бинарник — форвард-оракул перестановки `P` над 16-байтным блоком
(`in: 32 hex → out: 32 hex`, `out = P(in)`). Флага в бинарнике нет. Сервер
присылает случайный `y` и ждёт `x` с `P(x) = y` за `TIME_LIMIT` секунд; флаг —
награда. Значит, нужно восстановить `P` и построить `P⁻¹`.

## 0. Разведка

```sh
file minivm            # ELF 64-bit LSB, x86-64, statically linked, stripped
strings minivm | grep -i ctf    # пусто: ни флага, ни формата, ни сообщений
./minivm 00112233445566778899aabbccddeeff    # печатает P(block) в hex
```

В секции данных заметны: 256 байт — перестановка `0..255` (похоже на S-box) и
две 256-байтовые таблицы, похожие на таблицы умножения в GF(2⁸).

## 1. Слой 1: rolling-XOR над байткодом

Код VM лежит зашифрованным. Поток ключа позиционный (не зависит от ввода):

```
k = 0x5A
for each byte: pl=enc^k; k = (k*31 + 0x9E) & 0xFF
```

Сняв его, видим... почти ничего: одну инструкцию `UNPACK` и большую нулевую
область. Настоящей программы здесь нет — это ловушка для «статического дампа».

## 2. Слой 2: самомодификация (UNPACK)

`UNPACK pack_off, code_off, len` во время выполнения берёт `len` байт из данных
по `pack_off`, снимает с них splitmix64-поток и **пишет результат в код** по
`code_off`, после чего исполнение продолжается уже по восстановленным
инструкциям. Поток ключа:

```
st = 0x9E3779B97F4A7C15
for i in range(len): if i%8==0: st = splitmix64(st); ks_i = (st >> 8*(i%8)) & 0xFF
```

(`splitmix64` — стандартный `mix64` с константами `0x9E3779B97F4A7C15`,
`0xBF58476D1CE4E5B9`, `0x94D049BB133111EB`.) Сняв этот слой, получаем полную
программу `P`.

## 3. Полиморфная ISA

Числовые значения опкодов на каждой сборке переставлены. Карта
`байт → канонический опкод` лежит в данных как `vm_op_dec`, обфусцированная
`XOR 0x5A`. Сняв её, можно дизассемблировать (см. `disasm_vm.py`, который делает
шаги 1–3 автоматически и печатает мнемоники).

## 4. Опознаём SPN

Программа — это 10 раундов над 16-байтным состоянием:

```
AddRoundConstant  : state[i] ^= RCON[r][i]
SubBytes          : state[i]  = SBOX[state[i]]          (LDB по таблице SBOX)
ShiftRows         : перестановка байт (column-major, строка r сдвиг на r)
MixColumns        : по столбцам, out = M · col  над GF(2⁸), полином 0x11b
```

и финальный `AddRoundConstant`. Множители `×2` и `×3` в `MixColumns` и
структура `ShiftRows` — ровно как в AES, но S-box и раунд-константы кастомные
(их берём из таблиц в данных). Диффузия полная: каждый байт `y` зависит от всех
байт `x` → побайтовая атака невозможна.

## 5. Строим P⁻¹

Пораундно в обратном порядке:

```
state ^= RCON[R]
for r in R-1 .. 0:
    InvMixColumns(state)    # множители 9,11,13,14
    InvShiftRows(state)
    InvSubBytes(state)      # SBOX_INV
    state ^= RCON[r]
```

Эталонная реализация — [../src/spn.py](../src/spn.py) (`Params.inverse`). Проверка
`P⁻¹(P(x)) = x` на 2000 случайных блоков проходит; `spn.forward` совпадает с
выдачей бинарника.

## 6. Снимаем флаг

```sh
python3 solve.py <ip> 1338
```

Клиент читает `y`, считает `x = P⁻¹(y)`, присылает до истечения таймера и получает
флаг. Алгебраическая инверсия занимает доли миллисекунды — таймер (20 с) с огромным
запасом; узкое место — именно построить корректный инвертор, т.е. полностью и верно
разобрать VM.

## Замечания

- **Не патчить образ.** При любом изменении (несовпадение SHA-256 на старте) VM
  молча инвертирует младший бит выдач S-box — `P` считается неверно, но без
  ошибок: слепое патчение/обход условий уводит в сторону.
- **SMT.** Полную 10-раундовую `P` z3 вперёд за разумное время не инвертирует
  (в этом и смысл); модель на 1 раунд решается за секунды и годится для проверки
  корректности разбора. Основной путь — алгебраическая инверсия выше.
