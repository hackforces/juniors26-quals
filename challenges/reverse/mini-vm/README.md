# Чёрный ящик / The Black Box (reverse/hard)

## Условие (для игроков)

**RU:** Из лицензионной подсистемы одной конторы изъят чёрный ящик. Это
статический бинарник-оракул: считает некоторую функцию `P` над 16-байтным
блоком — подаёшь 32 hex-символа, получаешь 32 hex-символа `P(блока)`.
Внутри — самописная виртуальная машина, да ещё и переупаковывающая саму
себя. Экзаменатор при каждом подключении присылает случайное значение `y`
и требует за отведённое время найти `x`, такой что `P(x) = y`. Разобрать
`P` офлайн мало — нужно построить рабочую обратную функцию и успеть
ответить вживую.

**EN:** A black box has been seized from a company's licensing subsystem. It is a
static binary oracle computing some function `P` over a 16-byte block: feed it
32 hex characters and it returns 32 hex characters of `P(block)`. Inside sits a
hand-written virtual machine that even repacks itself. With every connection
the examiner sends a random value `y` and expects, within the time limit, an
`x` such that `P(x) = y`. Reversing `P` offline is not enough — you must build
a working inverse and answer live, in time.

> На обратной стороне дискеты маркером выведено: «На прямые вопросы ящик
> отвечает честно. Обратные — за плату. Плата — время».
>
> On the back of the floppy, someone has written in marker: "The box answers
> direct questions honestly. The reverse ones come at a price. The price is
> time."

## Запуск

```bash
CTF_FLAG='InnoCTF{...}' docker compose up -d --build
curl -o mini-vm-files.zip http://127.0.0.1:13403/    # бинарник minivm + записка
nc 127.0.0.1 13404
```

Смена флага — только перезапуск, без пересборки:

```bash
CTF_FLAG='InnoCTF{...}' docker compose up -d --force-recreate
```

Опционально `SEED` (build-arg) меняет S-box/константы `P` — другой инстанс
задачи; по умолчанию сборка детерминирована. `TIME_LIMIT`/`ROUNDS` — env
сервера (дефолты 20 секунд, 1 раунд).

## Проверка решения

```bash
python3 solve.py 127.0.0.1 13404   # эталонный решатель против локального сервера
```

## Описание

Участник получает статический stripped ELF x86-64 — **форвард-оракул** кастомной
обратимой перестановки `P` на 128-битном блоке. Секрета в бинарнике нет; флаг
живёт только в окружении сервера и выдаётся за доказанное умение инвертировать
`P` под таймером.

`P` — самописная **SPN** (10 раундов): `AddRoundConstant` → `SubBytes` (случайный
S-box) → `ShiftRows` → `MixColumns` (матрица MDS над GF(2⁸), полином `0x11b`),
плюс финальный `AddRoundConstant`. Диффузия `ShiftRows+MixColumns` за два раунда
делает каждый байт выхода зависящим от **всего** входа — побайтовое восстановление
исключено. При этом `P` чисто обратима пораундно (есть однозначный прообраз).

Защиты VM, повышающие цену реверса:

* **Слой 1** — байткод зашифрован rolling-XOR (`k₀=0x5A`, `k←31·k+0x9E`);
* **Слой 2 (самомодификация)** — в расшифрованном коде лежит лишь крошечный
  стаб `UNPACK` и нулевая область; настоящая программа `P` хранится в данных,
  зашифрованная splitmix64-потоком, и **восстанавливается в код во время
  выполнения**. Наивная статическая расшифровка показывает пустышку;
* **Полиморфная ISA** — на каждой сборке байты опкодов переставлены случайно;
  таблица `opcode→мнемоника` читается из бинарника (`vm_op_dec`), а не хардкодится;
* **Тихая порча при тампере** — старт сверяет SHA-256 образа; при любом патче
  VM молча инвертирует младший бит в выдачах S-box → `P` считается неверно,
  **без ошибок и падений** (правдоподобный, но неправильный hex);
* строки и таблица опкодов обфусцированы XOR.

Сервер (`nc`): на подключение берёт случайный `x0`, считает `y = P(x0)` самим
бинарником, присылает `y`, ждёт `x` за `TIME_LIMIT` секунд, принимает если
`P(x) = y` (проверка — тем же бинарником, так что сервер и хэндаут не расходятся).
После `ROUNDS` раундов отдаёт флаг.

## Решение

```sh
python3 solve.py <ip> 13404
```

Порядок (intended):

1. **Разведка**: `file`/`strings` — статический stripped ELF, в строках пусто
   (ни `InnoCTF{`, ни сообщений). В данных видны 256-байтовая перестановка (S-box)
   и таблицы умножения GF.
2. **Слой 1**: снять rolling-XOR с кода → виден только `UNPACK` + нули.
3. **Слой 2**: разобрать `UNPACK` (`pack_off, code_off, len`), снять splitmix64-поток
   (seed `0x9E3779B97F4A7C15`) с блоба в данных → настоящая программа.
4. **Полиморфизм**: снять `vm_op_dec` (XOR `0x5A`) → мнемоники.
5. **Опознать SPN**: `AddRoundConstant/SubBytes/ShiftRows/MixColumns ×10`, поле AES
   (множители ×2, ×3). Вытащить S-box, матрицу, раунд-константы.
6. **Построить `P⁻¹`**: `InvMixColumns` (9,11,13,14) → `InvShiftRows` →
   `InvSubBytes` → `ARC`, в обратном порядке раундов.
7. **Вживую**: `nc`, прочитать `y`, прислать `P⁻¹(y)` до истечения таймера → флаг.

Разбор и инструмент — [WALKTHROUGH.md](WALKTHROUGH.md), дизассемблер
[disasm_vm.py](disasm_vm.py), эталонный решатель [solve.py](solve.py)
(алгебраическая инверсия + демо SMT на одном раунде + негативные проверки
честности).

## Защита от непредусмотренных решений

- `strings minivm | grep -i innoctf` — **пусто**; флага в бинарнике/хэндауте нет
  вообще (проверяется `src/make_public.py` и решателем).
- Полная диффузия → побайтовый/частичный перебор невозможен; угадать `x` — `2¹²⁸`.
- Наивная rolling-XOR-расшифровка кода даёт только `UNPACK` + нули — нужно
  эмулировать самомодификацию (иначе статический разбор видит пустышку).
- Хардкод-таблица опкодов не переносится между сборками (полиморфизм) — её нужно
  извлечь из конкретного бинарника.
- Патч образа → тихо неверный (но валидный на вид) hex, без краха и сообщений →
  слепое патчение уводит в сторону.
- Статическая «подстановка» ответа не работает: `y` случаен каждую сессию, а
  таймер требует уже готовый инвертор (а значит — корректно и полностью
  разобранную `P`).

## Честно о пределах

Это файловый реверс плюс интерактив, а не крипто-препятствие: `P` публична и
обратима. Упорный реверсер (в т.ч. ИИ с отладчиком/эмулятором), полностью
восстановив `P`, построит инвертор и уложится в таймер. Интерактив ломает схему
«разобрал офлайн и вставил статический ответ» и делает обязательным рабочий код,
то есть корректный и полный реверс, — он поднимает цену, но не делает задачу
нерешаемой. Усиление против чисто офлайн-разбора (привязка к `rdtsc`/`ptrace`
или серверный параметр раунда) намеренно вынесено за рамки этой версии.

## Структура и локальная сборка

- `src/` — `chal.c`+`sha256` (бинарник-оракул), `gen_vm.py` (генератор байткода),
  `spn.py` (единый источник математики, само-тест `python3 src/spn.py`),
  `make_public.py` (сборка хэндаута с проверкой отсутствия утечек), `server.py`.
- `vm_blob.h` и `minivm` генерируются при сборке (`gen_vm.py`/`cc`) и в git не хранятся.

```bash
python3 src/gen_vm.py                       # -> src/vm_blob.h
clang -O2 -Wall -o minivm src/chal.c src/sha256.c -I src
CHAL_PATH=$PWD/minivm CTF_FLAG='InnoCTF{...}' python3 src/server.py   # локальный сервер
python3 solve.py 127.0.0.1 1337
```
