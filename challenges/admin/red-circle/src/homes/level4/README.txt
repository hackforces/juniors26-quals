КОНВЕРТ 4 из 5 — «туннель в никуда»
====================================

Ты в rbash (restricted bash). В PATH — только ssh, ls и id.
Пароль level4 ты уже знаешь — это ключ из конверта 3 (годится
и для ssh localhost: хост-ключи уже записаны в known_hosts).

ЦЕЛЬ: запустить /usr/local/bin/nextkey — он напечатает ключ
(пароль от level5; вход: ssh level5@<тот же хост и порт>).

Тупик №1: форс-команда ssh выполняется на сервере через твою же
ограниченную оболочку, поэтому
    ssh localhost /usr/local/bin/nextkey
не сработает: rbash на той стороне запретит слэш в имени команды.

ПОДСКАЗКА 1: у ssh-клиента есть опция  -o ProxyCommand=КОМАНДА.
             Она выполняется ЛОКАЛЬНО, на твоей стороне, ещё ДО
             соединения: вместо TCP-подключения её ввод/вывод
             становится «проводом» для ssh-протокола.
ПОДСКАЗКА 2: раз ProxyCommand исполняет любую команду локально —
             заставь её запустить полноценный shell и перенаправить
             его ввод-вывод на ТВОЙ терминал (/dev/tty):

    ssh -o ProxyCommand='/bin/sh -c "/bin/sh -i </dev/tty >/dev/tty 2>&1"' localhost

ПОДСКАЗКА 3: в полученном shell (приглашение $ ) запусти
             /usr/local/bin/nextkey. После exit «туннель» закроется
             сам и ты вернёшься в rbash.
             Быстрый вариант (сразу ключ, без shell):

    ssh -o ProxyCommand='/bin/sh -c "/usr/local/bin/nextkey >/dev/tty"' localhost

Ключевые слова: ssh ProxyCommand escape, GTFOBins ssh.
