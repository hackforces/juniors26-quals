# Дело о лавке предсказаний / The Fortune Shop (web/medium)

- Порт: `13438` (переопределяется через `PORT`; внутри контейнера `8080`)
- Флаг: только из env `CTF_FLAG` — попадает в базу только в момент
  покупки соответствующего товара; без флага контейнер отказывается
  стартовать, дефолтов нет
- Стек: FastAPI + SQLite (aiosqlite, WAL; один сервис в compose), флаг
  уезжает в базу только в момент покупки. Файл БД живёт в контейнере
  (`/app/data/app.db`): рестарт контейнера сохраняет прогресс, recreate
  инстанса — свежая база.

## Запуск

```bash
CTF_FLAG='InnoCTF{...}' docker compose up -d --build
open http://127.0.0.1:13438/
```

База — sqlite-файл в контейнере (`/app/data/app.db`): `docker compose
restart` сохраняет её, `down`/recreate — свежая база (для CTF это
нормально — аккаунты создаются на лету).

## Условие (для игроков)

**RU:** На ярмарке в Сохо открылась лавка, где механический прорицатель обещает
угадать, что завтра заблокирует Городской файрвол. Хозяин продаёт самый
любопытный товар лишь постоянным клиентам и только за верные предсказания.
Холмс хочет этот товар — но гадать не привык.

**EN:** A stall in Soho houses a mechanical fortune-teller that claims to know
what the City firewall will block tomorrow. Its keeper sells the most
curious item only to regular customers, and only for accurate predictions.
Holmes wants that item — and he never guesses.

Игрокам: лавка платит 10 очков только за идеально угаданный раунд — все 5
ответов верны, один промах обнуляет раунд. Флаг в магазине стоит 500 очков.
Форма регистрации требует email, а флаг… флаг просто очень дорогой.

## Решение

1. **Обход клиентской валидации**: API `/api/register` принимает
   `"email": null` — аккаунт без email логинится без кода подтверждения
   (код «из письма» никогда не отправляется).
2. **Детерминированный раунд**: в UI игры виден `seed` раунда;
   `/api/start_game` принимает ЛЮБОЙ seed от клиента — раунд полностью
   определяется сидом, один и тот же seed можно переиспользовать.
3. **Оракул `correct_count`**: `/api/submit` возвращает число верных
   ответов. Фиксируем один seed, держим 4 ответа и перебираем пятый по
   вариантам: вариант, повышающий счётчик, — верный. 5 вопросов × 6
   вариантов ≈ 30 раундов на том же seed восстанавливают весь ключ
   ответов, без обращения PRNG.
4. **Фарм и покупка**: реплеем того же seed с восстановленными ответами
   фармим по 10 очков до баланса 500 и покупаем флаг (`/api/buy`,
   сообщение товара подставляется из env при покупке).
