# Дело о спорном вердикте / The Contested Verdict (web/medium)

- Порт: `13437` (переопределяется через `PORT`; внутри контейнера `8080`)
- Флаг: только из env `CTF_FLAG` — уезжает исключительно в заголовке
  `X-Flag` исходящих запросов Lua-песочницы; без флага приложение
  отказывается стартовать
- Пароль панели жюри слабый и словарный (top-фрагмент rockyou) — подбор
- Пароль панели жюри слабый и словарный (top-фрагмент rockyou) — подбор
  пароля логин-формой входит в задумку. Переопределяется env `PASSWORD`.
- Стек: Flask + lupa (Lua-песочница). Судья ограничен по CPU (квота
  процессорного времени ~2.5 с: спин, включая pcall/coroutine/C-тяжёлые
  формы, останавливается жёстким `os.exit(137)` воркера) и по памяти
  (RLIMIT_AS 512 MiB на воркер).
- `GET /` для анонимов рендерит страницу входа напрямую (200, без
  302-редиректа на `/login`): пробы оркестратора бьют в `/` и ждут 2xx —
  редирект не проходит readiness. Форма логина постится в `/login`
  (явный `action`).

## Запуск

```bash
CTF_FLAG='InnoCTF{...}' docker compose up -d --build
open http://127.0.0.1:13437/
```

## Условие (для игроков)

**RU:** Инспектор Лестрейд засиделся над задачей в судейской системе «Вердикт
2050»: решение отклонено, а панель жюри заперта паролем. Холмс берётся
доказать, что жюри ошибается. Для начала — попасть внутрь.

**EN:** Inspector Lestrade is stuck on a task in the Verdict 2050 judging
system: the submission is rejected and the jury panel sits behind a
password. Holmes sets out to prove the jury wrong. Step one: get inside.

Игрокам: войдите в панель жюри (логин `admin`), отправьте решение на Lua
и разберитесь, куда на самом деле система может отправлять свои запросы
и что она прикладывает к ним. Для приёма флага понадобится собственный
слушатель (webhook.site или локальный HTTP-сервер).

## Решение

1. **Словарный подбор пароля** `admin` по rockyou (дефолт — слово из
   первой сотни, rate-limit намеренно нет): форма `/login` отвечает 302
   при успехе.
2. **Lua-решение**: в панели доступна функция исходящих запросов
   `fetch(url[, method[, body]])`; `check_url` требует, чтобы строка
   после `http(s)://` начиналась с `127.0.0.1` — «запросы только на
   собственный адрес».
3. **Userinfo-обход**: `http://127.0.0.1@<ваш-хост>/` проходит проверку
   (`rest.startswith("127.0.0.1")`), но `requests` отправляет запрос на
   `<ваш-хост>` — синтаксис userinfo в authority. Вариант того же класса:
   `http://127.0.0.1.<host>/`.
4. **Экфильтрация**: каждый исходящий запрос несёт заголовок
   `X-Flag: <флаг>` — слушатель игрока получает флаг.

Проверенные непреднамеренные пути закрыты: побег из Lua-песочницы не даёт
флага (значение живёт в замыкании Python, наружу торчит только через
заголовок), `/admin/flag` — заглушка, `..` в URL отклоняется, `secret_key`
случайный на старт. Зависшее/враждебное Lua-решение сдерживается тремя
поясами: (1) квота процессорного времени — `debug.sethook(…, "l")` на
каждой строке проверяет `os.clock()` (захвачен в апвьюч до зануления
глобалов прологом — отключить проверку из кода нельзя) против
`CPU_LIMIT_SECONDS = 2.5`; при превышении воркер умирает через
`os.exit(137)` («Judge error: cpu budget exceeded (hard stop)»).
Выбрано CPU-время, а не счётчик инструкций: у процессорного времени нет
слепых зон (свежие корутины по N-1 инструкций никогда не триггерят
счётчик, цикл из одной инструкции на 10 MB memcpy откладывал бы первое
срабатывание на сотни секунд); корутины хук не наследуют (Lua 5.5),
поэтому `coroutine.create/wrap/resume` подменены на обёртки,
устанавливающие хук на каждый поток при создании и на каждый resume.
(2) `RLIMIT_AS` 512 MiB на процесс воркера — одно-shot C-аллокации
(`("x"):rep(2^31)` — 2 GB malloc) падают как «not enough memory», не
задевая соседние инстансы. (3) wall-clock 30 с остаётся последним поясом
(блокирующиеся C-вызовы). Замер: CPU-бомбы умирают на ~2.57 с, легитимное
решение — 21 VM-инструкция, запас ~10^4×. Адверсариальный прогон —
`solve.py --probe` (7 кейсов, каждый должен укладываться в 5 с).

## Проверка решения

```bash
python3 solve.py   # полный путь против 127.0.0.1:13437 (stdlib only)
# adversarial-постура (CPU/память-бомбы против легитимного решения):
python3 solve.py --url http://127.0.0.1:13437 --probe
```

Солвер сам поднимает локальный слушатель и колбечется через
`host.docker.internal` (см. `extra_hosts` в compose); флаг печатается
в конце. `--expect` — опциональная проверка точного значения.
