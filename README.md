## 🎩 Сеттинг

Лондон по-прежнему узнаётся — но теперь обычные вещи оставляют сетевые
логи, личный транспорт сам согласует маршруты, а улики приходят как
запись, образ устройства или адрес сервиса. Шерлок Холмс и доктор Ватсон
работают с инспектором Лестрейдом, миссис Хадсон и другими знакомыми
фигурами. Каждая категория — законченный кейс со своим финалом; скрытого
суперзлодея и меты-флага между десятью концовками нет.

Правило названий: задача носит имя кейса, места или свидетеля — но никогда
название приёма или инструмента атаки. Категория — не спойлер, а способ
разложить работу по столам.

> **Важно про spoilers.** Внутри каталога каждой задачи лежит её полное
> решение (`README.md` пакета и `solve.py`). Открывайте, когда решили —
> или когда окончательно сдались.

## 🎮 Как играть

Каждая задача — самодостаточный Docker-сервис: поднимается одной
командой, а флаг задаёте вы сами через переменную окружения. Локально вы
сами себе организатор: сколько задач подняли — столько и играете.

Единственное исключение — OSINT: там поднимать нечего, материалы уже
лежат в `attachments/` пакета.

### 1. Поднять задачу

```bash
git lfs install                              # один раз (в репо есть LFS-хэндауты)
git clone <адрес этого репозитория>
cd challenges/crypto/easy-yaponskij-veer    # или любая другая

CTF_FLAG='InnoCTF{...}' docker compose up -d --build
```

Как подключиться — зависит от категории:

- **web / crypto / forensic / network / stego / reverse** —
  открывайте `http://127.0.0.1:<порт>` (порт — в README задачи);
- **admin / privilege_escalation** — `ssh player@127.0.0.1 -p <порт>`
  (логин и пароль — в README задачи);
- **pwn** — `nc 127.0.0.1 <порт>`, а бинарник с libc лежит на
  http-порту того же пакета;
- **osint** — ничего не поднимать: материалы в `attachments/` пакета.

Хэндауты (pcap, архивы, картинки, ELF) сервисы раздают сами с http-порта —
скачиваемые артефакты собираются в образе из исходников и совпадают с
сервисом байт-в-байт.

### 2. Решить и взять флаг

Флаг — ровно то, что вы положили в `CTF_FLAG` при старте. Хотите другой
флаг — перезапустите пакет с `--force-recreate`: артефакты пересоберутся
под новый, без пересборки образа.

### 3. Проверить себя

В каждом пакете есть `solve.py` — эталонный решатель против живого
инстанса (по умолчанию `127.0.0.1:<порт пакета>`):

```bash
python3 solve.py
```

Прошёл — значит задача решена безупречно. Полный цикл
«build → health → solve → down» одной командой:

```bash
bash scripts/local_smoke.sh <каталог пакета>
```

Мелкий шрифт: pwn-солверы требуют `pwntools`, ssh-категории — `sshpass`
на хосте; guard `${CTF_FLAG:?…}` действует на любые compose-команды, так
что для `ps`/`down` делайте `export CTF_FLAG=…`.

```
├── src/                 # исходники сервиса
├── attachments/         # хэндауты для игрока (у osint — единственный «инстанс»)
├── solve.py             # эталонное решение (оно же тест пакета)
└── README.md            # условие, запуск и полный разбор
```

OSINT-пакеты устроены проще: `attachments/` + `solve.py` + `README.md`,
без Docker.

Принципы сборника, единые для всех пакетов:

- флаг попадает в контейнер **только** через env `CTF_FLAG` — ни один
  образ, слой, файл или коммит его не содержит;
- всё, что скачивают игроки, генерируется из флага в рантайме и
  воспроизводится при перезапуске;
- `solve.py` — не украшение, а тест: солвер обязан сходиться к флагу
  против живого инстанса.
